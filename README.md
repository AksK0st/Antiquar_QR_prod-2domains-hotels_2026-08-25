# Antiquar QR — каталог исторических предметов

Веб-приложение для управления цифровым каталогом исторических и антикварных предметов с доступом к информации через QR-коды.

Проект разработан для двух гостиниц: «Галерея» и арт-отеля «Моцарт». Посетители могут сканировать QR-коды рядом с экспонатами и просматривать их фотографии, описания и историческую информацию.

Система включает публичный интерфейс, административную панель для управления каталогом и серверную инфраструктуру.

## Возможности

**Публичная часть**
- Просмотр каталога предметов и их описаний.
- Просмотр фотографий экспонатов.
- Переход к предмету по QR-коду.
- Поддержка нескольких гостиниц в рамках одного приложения.

**Административная панель**
- Авторизация администраторов.
- Создание, редактирование и удаление предметов.
- Управление коллекциями и фотографиями.
- Загрузка и обработка изображений.
- Журналирование административных действий.

**Backend и инфраструктура**
- REST API на FastAPI.
- Асинхронная работа с PostgreSQL через SQLAlchemy.
- Хранение изображений в MinIO (S3-compatible).
- Миграции базы данных через Alembic.
- Контейнеризация с Docker Compose.
- HTTPS и маршрутизация через Caddy.
- Автоматизированные проверки в GitHub Actions.
- Резервное копирование PostgreSQL и MinIO.

В production внешние запросы обрабатываются через Caddy. Backend, PostgreSQL и MinIO работают во внутренней Docker-сети.

Приложение поддерживает два домена с общей серверной инфраструктурой и разделением публичного контента по гостиницам.

### QR-маршрутизация

Каждый предмет имеет постоянный UUID (`public_id`), который используется для формирования ссылки:

`/i/<uuid>`

Благодаря этому изменение названия или URL-slug предмета не приводит к необходимости перепечатывать QR-код.

### Работа с изображениями

Загружаемые изображения проходят серверную обработку: проверку формата и размеров, нормализацию ориентации и повторное кодирование перед сохранением в MinIO.

### Безопасность

- Серверные сессии администраторов.
- Защищённые HttpOnly/Secure cookies.
- Ограничение частоты попыток авторизации.
- Валидация загружаемых файлов.
- Изоляция внутренних сервисов.
- Аудит административных операций.

## Локальный запуск

**Требования:** Docker и Docker Compose.

Клонировать репозиторий:

```bash
git clone <repository-url>
cd <repository-directory>
```

Создать файл окружения на основе `.env.example` и при необходимости настроить переменные.

Запустить приложение:

```bash
docker compose up --build
```

После запуска:

| Сервис | Адрес |
|---|---|
| Frontend | http://localhost:5173 |
| Backend API | http://localhost:8000 |
| Swagger UI | http://localhost:8000/docs |
| MinIO Console | http://localhost:9001 |

## Тестирование

Backend:

```bash
python -m pytest -q backend/tests
```

Frontend:

```bash
cd frontend
npm ci
npm run lint
npm run build
```

CI проверяет сборку приложения, миграции, авторизацию, CRUD-операции, обработку изображений и работоспособность основных маршрутов.

## Production

Для production используется отдельная Docker Compose-конфигурация с HTTPS, проверками готовности сервисов, миграциями и процедурами резервного копирования.

Подробные инструкции по развёртыванию и обслуживанию рекомендуется хранить в `docs/DEPLOYMENT.md`.
